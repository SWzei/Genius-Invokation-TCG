# 2026-11 GLM Validation（D30）

> 2026-11-14 / 15，对智谱开放平台（`open.bigmodel.cn`）的**真实调用**，不含任何 Mock。
> 上一轮（D29）的模型接入层只对本地仿真服务测过；本报告是它第一次面对真实服务的记录。

## 0. 结论

1. **端到端可用**：`glm-5.3` 打完 85 局完整对局（84 局计入评测 + 1 局被中断运行留下），另在平台房间打 1 局，另有 404 次场景题调用；
   **零引擎回退、零无效局、零降级局**。模型首答即合法的比例 99.4%–99.9%，其余经一次追问全部得到合法答案。
2. **状态理解**：读局面 560 问全对；隐藏信息题 75 问中 73 次回答"无法得知"。
3. **真实服务暴露了 5 个仿真测试测不到的问题**，都已修复并加了测试（§3）。其中最重要的一条：
   余额不足时接口返回的是 HTTP 429，旧代码会把它当限流重试，然后让回退策略悄悄把整局打完。
4. **性能**：每次调用中位 4.0 秒、p90 8.2 秒、p99 15.0 秒；一局约 50 次调用、4.4 分钟。
5. **用量**：`glm-5.3` 共记录 5,051 次调用，输入 1,012 万 token、输出 94 万 token（其中 79% 是思考）。
   按公开美元价目估算约 16.9 美元；实际走的是 Coding Plan 套餐额度，不按 token 计费。

## 1. 密钥与端点

| 项 | 做法 / 结果 |
|---|---|
| 密钥存放 | 仓库之外的文件（权限 600），只以环境变量 `ZAI_API_KEY` 注入进程 |
| 密钥去向 | 只发往 `open.bigmodel.cn`；放在 `Authorization` 头里，不进 URL |
| 是否落盘 | 调用日志只记档案名、提示词哈希与长度、状态码、延迟、token；**不含提示词与密钥**。交付前对仓库、数据、报告全文检索密钥的两段，均无命中 |
| 配置 | `configs/models.toml` 只写环境变量名；配置里出现密钥字段会被拒绝加载（D29 既有行为） |
| **建议** | 密钥曾以明文出现在对话里，测试结束后请在控制台作废重建 |

两个端点的实测差异：

| 端点 | 结果 |
|---|---|
| 通用 `…/api/paas/v4` | 免费模型可用（`glm-4.7-flash`、`glm-4.5-flash`、`glm-4-flash`）；付费模型（`glm-5.3`、`glm-5.3-flash`、`glm-5.3-flashx`）全部返回 **HTTP 429 + 错误码 1113"余额不足或无可用资源包"** |
| Coding Plan `…/api/coding/paas/v4` | `glm-5.3`、`glm-5.3-flash` 可用 |

`glm-5.3-pro` 这个模型 id 不存在（HTTP 400，错误码 1211）。
正式实验使用 Coding Plan 端点上的 `glm-5.3`（档案 `glm-53-plan`）。官方文档写明该套餐面向 Coding Agent；
用于对局评测是在账户持有人明确确认后进行的，是否符合套餐条款由账户持有人判断。

## 2. 真实服务的行为（与文档 / 预期的出入）

| 观察 | 证据 | 对应处理 |
|---|---|---|
| `glm-5.3` 系列**不能关闭思考**：传 `thinking.type = disabled` 返回 HTTP 400、错误码 1210 | 实测 + 官方文档 | 档案改用顶层 `reasoning_effort = "low"`（可选 `low` / `high` / `max`） |
| 思考 token 计入输出并占用 `max_tokens`；额度不够时**正文为空**、`finish_reason = length` | `glm-4.7-flash` 在 256 上限下空回复；`glm-5.3` 首局有一次思考跑满 4,096 token、耗时 73 秒后空回复；另见到 1 次思考正常结束但正文为空 | `max_tokens` 取 2,048；空回复追问一次；错误说明里写出思考占了多少 |
| 余额不足用 HTTP 429 表达 | 通用端点实测 | 归类为 `quota`，不重试，并停止该客户端的后续请求 |
| `/models` 列表不完整：未列出的 `glm-4-flash` 实际可调 | 实测 | 以实际调用为准，不依赖列表 |
| JSON 模式下 `glm-4.7-flash` 会把答案再包一层 `{"answer": "…"}` | 冒烟测试 | 解析器按约定字段取值，不匹配则追问；`glm-5.3` 未出现 |
| 免费档首个请求耗时约 30 秒 | 冒烟测试 | 免费档不适合带计时的对局 |
| 用量字段含 `prompt_tokens_details.cached_tokens` 与 `completion_tokens_details.reasoning_tokens` | 实测 | 两者都进调用日志与汇总 |

## 3. 因真实接口而改的代码

| 问题 | 改动 | 测试 |
|---|---|---|
| 余额不足（429 + 1113）被当限流反复重试 | `classify_http_error`：按状态码、服务商错误码、报错措辞分出 `quota` / `model_not_found` / `blocked` / `auth` / `rate_limit` | 仿真服务按真实报文形状回放 |
| 致命错误后回退策略继续把整局打完 | `FATAL_KINDS`：首次致命错误后客户端置为停用，后续请求不再发出；对局套件见到致命错误立即停止该受试者 | 同上；套件测试 |
| 思考耗尽输出额度导致空回复 | 空回复算一次可追问的失败（传输层失败仍不追问）；说明里给出思考 token 数 | 仿真 + 真实对局 |
| 没有记录缓存命中与思考 token | `ChatResult` / 调用日志 / 汇总增加 `cached_tokens`、`reasoning_tokens`；档案增加 `price_cached_in` | 单测 |
| "执行合法率"掩盖模型自身的出错 | `DecisionTrace` 增加首答是否合法及原因；汇总按请求类型给出首答合法率、决策耗时 p50 / p90 / 最大值 | 单测 + 实测 |

## 4. 验证项逐条

| 要求 | 怎么测的 | 结果 |
|---|---|---|
| 真实服务调用 | `scripts.llm_smoke` + 全部实验 | 通过；HTTP 层面 5,223 次记录在案的调用全部 200 |
| 完整对局 | `lite` 套件 85 局；平台房间 1 局 | 全部打到终局；零引擎回退 |
| 状态理解 | 场景集读局面题（出战角色、双方血量、骰子、手牌数、回合） | 560 / 560（`glm-5.3`）；420 / 420（`glm-5.3-flash`） |
| 不臆测隐藏信息 | "X 是否在对方手牌中"（X 确实在；正确答案是无法得知） | 73 / 75；另 2 次答"没有" |
| 合法行动 | 首答合法率，按请求类型 | 见下表 |
| 知识增强 | `#kb=rules`、`#kb=rules-strategy` 各 28 局 + 场景题 | 知识进入提示词（token / 决策 1,540 → 2,381 → 2,763）；**强度没有测出收益**（Benchmark 报告 §2.2） |
| 异常处理 | 真实触发：余额不足、模型不存在、禁止关闭思考、空回复、无法解析、限流重试 | 均按预期归类；空回复与无法解析经追问恢复 |
| 成本控制 | `--max-calls 12000` 全局上限；逐调用记账 | 实际 4,422 次（计入报告的对局），未触顶。预算拦截逻辑本身只有离线测试，真实运行中没有触发过 |
| 带计时的真实对局环境 | 本地上游服务端，每步 45 秒 | 81 个决策零超时，最慢一步 32.6 秒，最小剩余 57 秒 |

首答合法率（`glm-5.3`，85 局合计）：

| 请求类型 | 询问 | 首答合法 | 比例 |
|---|---|---|---|
| 行动 | 3,416 | 3,406 | 99.71% |
| 重掷骰子 | 631 | 631 | 100% |
| 挑牌 | 169 | 163 | 96.45% |
| 选出战角色 | 105 | 105 | 100% |
| 起手换牌 | 85 | 85 | 100% |
| 合计 | 4,406 | 4,390 | 99.64% |

16 次首答不可用：14 次空回复（几乎都是思考用满输出额度，见 §5），2 次无法解析。追问后 16 次全部得到合法答案，没有一次落到回退策略。
"挑牌"的比例偏低只来自 6 次空回复，样本小，不足以说明这类决策更难。

## 5. 性能

`glm-5.3`，`reasoning_effort = low`，Coding Plan 端点，2–5 路并发：

| 指标 | 数值 |
|---|---|
| 调用延迟（成功的 5,035 次） | p50 3.95 s · p90 8.15 s · p99 14.96 s · 最大 38.1 s |
| 空回复（16 次） | 15 次是思考用满输出上限：上限 2,048 时每次 34–43 秒，首局试跑上限 4,096 时 73 秒——这是延迟长尾的主要来源；另 1 次思考 60 token 后正常结束（`finish_reason = stop`）但正文为空，2.1 秒 |
| 需要重试的调用 | 8 / 5,051（0.16%） |
| 10 路并发探测 | 10 / 10 成功，其中 3 次经过重试 |
| 每局 | 约 50–53 次调用；墙钟均值 263 秒（约 56 个决策、7.4 回合） |
| 输出中思考占比 | 78.6% |
| 输入中缓存命中占比 | 12.2% |

`glm-5.3-flash`（172 次，场景题）：p50 3.25 s、p90 7.0 s、最大 68 s；并不比旗舰快多少，斩杀题略低（0.69 对 0.75，差别不显著）。

- 估算单价取 docs.z.ai 的美元价目（每百万 token：输入 1.40、缓存命中 0.26、输出 4.40）。**实际没有按 token 扣费**——
  调用走的是 Coding Plan 套餐额度；套餐额度消耗了多少以控制台为准，我没有读取账户页面。
- 单局成本（按同一价目）：无知识约 0.12 美元；+ 规则约 0.19；+ 规则 + 策略约 0.22。

  `#detail=0` 去掉牌面文字，或不加知识。

## 7. 没有验证的事项

1. **只测了智谱一家**。OpenAI、Anthropic、Gemini、DeepSeek 的真实服务仍未调用过（没有密钥）；它们的错误分类规则按文档写成，未经真实报文检验。
2. **`reasoning_effort = high` / `max` 没有测**——延迟与输出会明显增加，是否换来更强的对局表现未知。
3. **通用端点上的付费模型没有打过对局**（余额不足）；Coding Plan 端点与通用端点上的同名模型是否行为一致，没有比较。
4. **套餐额度上限没有触发过**，对应的报错形状未知；若它不是 1113，会被归为一般限流而重试。
5. 预算上限、单局调用上限在真实运行中没有被触发，只有离线测试。
6. 单一提示词模板、单一温度（档案默认）；提示词写法对结果的影响没有测。

## 8. 复现

```bash
export ZAI_API_KEY=<你的密钥>                       # 不要写进任何文件
python -m scripts.llm_smoke glm-53-plan glm-flash   # 连通性；余额不足时会看到 error=quota、attempts=1
python -m bench.run --suite lite --replicates 1 --subjects "llm:glm-53-plan" --tag my_glm --workers 3 --max-calls 6000
python -m bench.scenarios eval --name v1 --subjects "llm:glm-53-plan" --tag my_scen --workers 3
```

原始记录：`data/bench/lite_glm53/{games,calls}.jsonl`、`data/bench/scen_v1/{scenarios,calls}.jsonl`、
`data/llm_arena/glm_first*.jsonl`、`data/platform/local_glm53/`（`data/` 不入库）。
