# 2026-11 Benchmark（D30）

> 环境：云端 2 核 / 8 GB，Python 3.12，`gitcg 0.21.0`（引擎默认规则 = 最新卡池）。日期 2026-11-14 / 15。
> 设计与用法见 `docs/howto/benchmark.md`；本报告记录实际跑出的数字。原始数据在 `data/bench/<tag>/`，汇总在 `reports/bench/`。
> **全部是模拟器内结果**，对手最高为脚本专家，没有对人类标定；LLM 玩家不进强度验收。

## 0. 结论

1. **评测体系已实现并跑通**：对局套件（对手阶梯 × 牌组 × 规则版本 × 先后手，所有受试者同种子逐局配对）+ 决策场景集
   （292 个场景，斩杀答案由引擎逐选项核实）。可续跑、带预算、带套件指纹；17 项测试（13 快 + 4 慢）。
2. **GLM-5.3 在 `lite` 套件上明显强于启发式基线**：28 局 0.929 [0.77, 0.98]；与启发式在相同 28 个格子上配对，
   分差 +0.41 [+0.24, +0.59]，13 局更好、0 局更差（符号检验 p < 0.001）。对脚本专家对手 6 / 8。
3. **知识注入没有测出收益，方向偏负**：加"规则 + 策略"后 0.786，配对 0 好 / 4 差（p = 0.125）；只加规则 0.857，0 好 / 2 差（p = 0.5）。
   样本量不足以判定"有害"，但可以说**没有任何一局因为加了知识而由负转胜**，同时每局 token 增加 63%–86%。
4. **单步决策上 GLM-5.3 与启发式持平**：斩杀局面 75% 对 77%（随机 12%）。模型的整局优势不来自"看见斩杀"，
   这类场景也区分不了它与一条简单规则。读局面 560 问全对；隐藏信息题 75 问中 73 次回答"无法得知"。
5. **这些数字不能说明真人竞技水平**，也不是强度认证：`lite` 每个受试者只有 28 局。

## 1. 设计要点（详见 howto）

| 要求 | 做法 |
|---|---|
| 不同强度对手 | `L0-random` → `L1-heuristic` → `L2-expert`（脚本专家）三级阶梯 |
| 不同牌组 | 脚本池牌组；赛事真实牌表的 `test` 划分（无脚本专家、未进过采集牌池） |
| 规则版本 | 同一批真人牌表分别在其原生版本（v6.3.0）与引擎最新规则下各打一组 |
| 典型决策场景 | 斩杀（引擎核实）、专家一致率、读局面、隐藏信息探针 |
| 独立测试数据 | 保留种子区段 7,100,001 起（场景集另起 7,600,001）；仓库的采集与训练不使用该区段；永不使用种子 0 |
| 配对与区间 | 胜率 Wilson 95%；配对差给区间、更好 / 更差局数与精确符号检验 |
| 防"回退策略替打" | 模型作答率 < 90% 的局标为降级并剔除；致命接口错误立即停止 |
| 可复现 | 套件 lock 文件（展开后的格子 + 真人牌表卡牌）、指纹校验、`engine.lock` 随运行保存 |

## 2. 对局套件 `lite`

56 个格子（2 套脚本池牌组 × 4 个对手 × 2 座位 × 2 轮种子 = 32；2 套真人牌表在 v6.3.0 下 × 2 个对手 × 2 座位 × 2 轮 = 16；
同两套牌表在最新规则下 × 1 个对手 × 2 座位 × 2 轮 = 8）。模型受试者只打第 1 轮种子（28 格），参照组打全 56 格；
下表统一限制在**模型打过的 28 个格子**上（`reports/bench/lite_all.md`，由 `python -m bench.compare` 生成）。

### 2.1 胜率

| 受试者 | 局数 | 总体 | 对随机 | 对启发式 | 对脚本专家 |
|---|---|---|---|---|---|
| GLM-5.3（无知识） | 28 | **0.929** [0.77, 0.98] | 8 / 8 | 12 / 12 | 6 / 8 |
| GLM-5.3 + 规则 | 28 | 0.857 [0.69, 0.94] | 8 / 8 | 12 / 12 | 4 / 8 |
| GLM-5.3 + 规则 + 策略 | 28 | 0.786 [0.60, 0.90] | 8 / 8 | 10 / 12 | 4 / 8 |
| `heuristic` | 28 | 0.518 [0.34, 0.69] | 6.5 / 8 | 6 / 12 | 2 / 8 |
| `expert:<deck>`（仅脚本池牌组的 16 格） | 16 | 0.656 [0.41, 0.84] | 4 / 4 | 3.5 / 4 | 3 / 8 |
| `legal_random` | 28 | 0.250 [0.13, 0.43] | — | — | — |

（平局计 0.5。`expert:<deck>` 只有在有脚本专家的牌组上才有格子可打。）

### 2.2 配对比较（相同格子，参照 = GLM-5.3 无知识）

| 对比 | 配对数 | 分差 | 95% 区间 | 更好 / 更差 / 相同 | 符号检验 p |
|---|---|---|---|---|---|
| + 规则 | 28 | −0.071 | [−0.17, +0.03] | 0 / 2 / 26 | 0.500 |
| + 规则 + 策略 | 28 | −0.143 | [−0.27, −0.01] | 0 / 4 / 24 | 0.125 |
| `heuristic` | 28 | −0.411 | [−0.59, −0.24] | 0 / 13 / 15 | < 0.001 |
| `expert:<deck>` | 16 | −0.219 | [−0.42, −0.02] | 0 / 4 / 12 | 0.125 |
| `legal_random` | 28 | −0.679 | [−0.81, −0.54] | 0 / 24 / 4 | < 0.001 |

读法：

- **模型对启发式的优势是可靠的**（两种检验一致）。
- **知识两行的正态区间与符号检验结论不一致时以符号检验为准**：只有 2–4 个不一致对，正态近似不可靠。
  结论是"没有测出差别，观察到的全部差别都朝负方向"。
- 对 `expert:<deck>` 的 +0.22 只有 16 对、4 个不一致，同样不够下结论。

### 2.3 分层（GLM-5.3 无知识）

| 轴 | 结果 |
|---|---|
| 牌组类别 | 脚本池牌组 14 / 16；真人牌表 12 / 12 |
| 规则版本 | 最新规则 18 / 20；v6.3.0 8 / 8 |
| 先后手 | 0 号位 13 / 14；1 号位 13 / 14 |

真人牌表上的 12 / 12 不代表"泛化得更好"：这两组的对手只到启发式，没有脚本专家（真人牌表没有对应的专家）。
**"没见过的牌组"这一轴目前只能测到 L1 强度**，这是套件的结构性限制。

| 受试者 | 询问决策数 | 首答合法率 | 最终由模型决定 | 回退 | 决策耗时 p50 / p90 / 最大（秒） | token / 决策 | 调用 / 局 | token / 局 |
|---|---|---|---|---|---|---|---|---|
| GLM-5.3（无知识） | 1,406 | 99.64% | 100% | 0 | 3.6 / 6.6 / 45.1 | 1,540 | 50.4 | 77,352 |
| + 规则 | 1,482 | 99.87% | 100% | 0 | 4.4 / 8.6 / 45.5 | 2,381 | 53.0 | 126,046 |
| + 规则 + 策略 | 1,460 | 99.38% | 100% | 0 | 3.9 / 8.0 / 46.2 | 2,763 | 52.5 | 144,075 |

84 局零引擎回退、零无效局、零降级局。首答不可用共 16 次：14 次是正文为空（几乎都是模型把输出额度全用在思考上），2 次是回复无法解析；
追问一次后全部得到合法答案。接口层面的细节见 GLM Validation 报告。

## 3. 决策场景集 `v1`

40 局源对局（20 套脚本池牌组的脚本专家互打，最新规则，种子 7,600,001 起）→ 292 个场景：
斩杀 52（其中 34 个是胜方的最后一个决策，18 个是之前 1–3 个决策里已经存在当场获胜的选项）、专家一致 160、读局面 80（每个 7 问 + 1 道隐藏信息题）。
斩杀场景平均 12.1 个选项、1.56 个获胜选项，逐题随机水平的均值 0.175。

| 受试者 | 斩杀（选中获胜选项） | 其中：最后一个决策 | 其中：更早的决策 | 专家一致率 | 读局面 | 隐藏信息题 |
|---|---|---|---|---|---|---|
| GLM-5.3 | 0.750 [0.62, 0.85]（n=52） | 0.853（n=34） | 0.556（n=18） | 0.244（n=160） | 560 / 560 | 73 / 75 答"无法得知" |
| GLM-5.3 + 规则 + 策略 | 0.769 [0.64, 0.86]（n=52） | 0.853 | 0.611 | 0.283（n=60） | — | — |
| GLM-5.3-Flash | 0.692 [0.56, 0.80]（n=52） | 0.824 | 0.444 | 0.233（n=60） | 420 / 420 | 56 / 56 |
| `heuristic` | 0.769 [0.64, 0.86]（n=52） | 0.882 | 0.556 | 0.175（n=160） | — | — |
| `legal_random` | 0.115 [0.05, 0.23]（n=52） | 0.118 | 0.111 | 0.144（n=160） | — | — |

斩杀题逐题配对（对 GLM-5.3）：`heuristic` 4 好 / 3 差（p = 1.0）；+ 知识 3 好 / 2 差（p = 1.0）；Flash 3 好 / 6 差（p = 0.51）；随机 3 好 / 36 差（p < 0.001）。

读法：

- **斩杀题把"会打"和"乱打"分得很开（0.75 对 0.12），但分不开 GLM-5.3、Flash 与启发式。** 作为"模型有没有基本战术能力"的门槛有用，作为排名指标区分度不够。
- "更早的决策"一栏约 0.5 不一定是错：先打一张不耗行动轮次的牌再斩杀同样能赢。脚本专家自己在这 18 题上按构造都没有当场拿下（它们后来也赢了）。
  所以这一栏读作"桌上有胜利时是否直接拿"，不是错误率。
- **专家一致率全部很低（0.14–0.28），随机就有 0.14。** 它衡量"像不像这套脚本"，而 GLM-5.3 在整局里赢了这些脚本 6 / 8——这个指标不能当质量用。
- 读局面全对，说明提示词里的局面表述是可读的；2 次把"无法得知"答成"没有"是臆测隐藏信息的实例（2 / 75）。

## 4. 现有神经策略

云端只有 D28 最小闭环留下的小模型 `bc_dgn_b0`（单牌组 `double_geo_navia` 上的行为克隆），**不是项目的正式基线**
（正式 checkpoint 在其他机器上，本次没有接触）。它只会打这一套牌，所以放在单牌组套件 `home`（16 格）上：

| 受试者 | 总体 | 对随机 | 对启发式 | 对脚本专家 |
|---|---|---|---|---|
| `neural:bc_dgn_b0#t=0` | 0.812 [0.57, 0.93] | 4 / 4 | 3 / 4 | 6 / 8 |
| `expert:<deck>` | 0.750 [0.51, 0.90] | 4 / 4 | 2 / 4 | 6 / 8 |
| `heuristic` | 0.625 [0.39, 0.82] | 4 / 4 | 2 / 4 | 4 / 8 |
| `legal_random` | 0.125 [0.04, 0.36] | 2 / 4 | 0 / 4 | 0 / 8 |

16 局只够确认"流程对神经策略可用、排序合理"；神经对专家、对启发式的差都不显著（p = 1.0、0.25）。
把正式 checkpoint 放进 `core` 套件（480 格）才是有意义的比较，见 §6。

## 5. 评测过程中发现并修复的问题

| 问题 | 影响 | 处理 |
|---|---|---|
| 局面结构里 `winner` 在对局进行中恒为 0（快照用 0 表示"尚无胜者"） | 接口与回放返回的结构化局面里该字段在对局中为 0，读起来像"0 号位已获胜"；提示词文本与界面显示不使用它 | `reps/describe.py` 改为终局才给出；加测试 |
| 余额不足被当作限流重试，回退策略会把整局打完 | 评测会在无人察觉时测到回退策略而不是模型 | 接口层归类为致命错误并停止后续请求；套件层降级局剔除 + 致命即停（见 GLM Validation） |
| 首答合法率此前没有单独统计 | "执行合法率 100%"掩盖了模型自己答错的次数 | `DecisionTrace` 增加首答是否合法及原因，按请求类型汇总 |

## 6. 局限与下一步

1. **样本量**。`lite` 28 局的总体胜率半宽约 ±0.1–0.18；知识配置的比较需要约 4 倍样本才可能定论
   （现有不一致对比例约 7%–14%）。补第 2 轮种子即可翻倍：`python -m bench.run --suite lite --tag lite_glm53 --replicates 2 …`（同一 tag 续跑）。
2. **对手上限是脚本专家**。GLM-5.3 已经赢下 6 / 8，阶梯顶端需要更强的对手：正式神经 checkpoint、带搜索的策略，或真人（`docs/howto/platform.md`）。
3. **真人牌表轴只到启发式对手**。让神经或模型策略去驾驶对面的真人牌表可以补上 L2。
4. **`core` 套件（480 格）没有跑过任何受试者**——它是为正式 checkpoint 准备的（约 1 CPU·小时 / 受试者）。
5. **规则版本轴**只覆盖 v6.3.0 与最新；引擎支持 v3.3.0–v7.2.0 共 36 个版本，但测试划分里的真人牌表目前只取了 v6.3.0。
6. **场景集只有引擎能直接核实的一类战术题**。需要多步规划的决策（抢先手、资源取舍）要用反事实评价（D28）做标签，成本高、检验力低，本次没有纳入。
7. 知识注入只比较了三种配置、一个模型、一种提示方式；"没有收益"的结论只对这个组合成立。

## 7. 复现

```bash
python -m bench.run --suite lite --subjects heuristic legal_random "expert:<deck>" --tag lite_refs --workers 2
python -m bench.run --suite lite --replicates 1 --tag lite_glm53 --workers 3 --max-calls 12000 \
    --subjects "llm:glm-53-plan" "llm:glm-53-plan#kb=rules-strategy" "llm:glm-53-plan#kb=rules"
python -m bench.compare --tags lite_glm53 lite_refs --reference "llm:glm-53-plan" --common-cells --out lite_all \
    --subjects "llm:glm-53-plan" "llm:glm-53-plan#kb=rules" "llm:glm-53-plan#kb=rules-strategy" heuristic "expert:<deck>" legal_random
python -m bench.scenarios eval --name v1 --tag scen_v1 --subjects "llm:glm-53-plan" heuristic legal_random
python -m bench.run --suite home --tag home_refs --subjects "neural:<ckpt>#t=0" "expert:<deck>" heuristic legal_random
```

口径：套件 `lite` 指纹 `2b88ef20714c8993`、`home` 指纹 `f35aac2ff5744995`；场景集 `v1`（`bench.scenarios/1`）；
模型档案 `glm-53-plan`（`glm-5.3`，`reasoning_effort = low`，`max_tokens = 2048`）；知识档案 `rules` / `rules-strategy`（`configs/knowledge.toml`）；
策略种子 1；日期 2026-11-14 / 15。`lite_glm53` 的原始数据里另有 1 局 `#kb=strategy`（一次被中断的运行留下的），未计入任何表。
