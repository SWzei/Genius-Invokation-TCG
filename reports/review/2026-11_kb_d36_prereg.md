# D36 预先登记

> 写于 2026-11-23 01:40（太平洋时间），在 D36 的任何对局（train / dev / test）之前。之后只追加，注明时间与原因。
> 每轮的具体候选在看到 train 分析之后、**任何 dev 结果之前**追加到本文件。

## 1. 目标与判据（用户给定）

- **目标**：新版本（带知识库）对不带知识库，双方用同一套观测层，在全新的 test 种子上镜像对战，**胜率 ≥ 0.7 且 p < 0.05**，约 150 对。
- **守门**：对脚本专家的锚点、斩杀转化题都不能显著变差。
- **对照组**：另加一组"旧观测层、不带知识库"，单独估计观测层的贡献。

## 2. 固定配置

| 名称 | 规格 | 用途 |
|---|---|---|
| `none_new` | `llm:deepseek-flash#reply=reason_first,elements=1` | 镜像对手（新观测层：状态文本标出角色元素，D35 采纳） |
| `none_old` | `llm:deepseek-flash#reply=reason_first` | 旧观测层，只用于观测层对照 |
| `v10` | `llm:deepseek-flash#kb=kbt3-trig,reply=reason_first,elements=1` | 父版本（知识库 v1.0，D33 的接入方式） |

都是非思考、温度 0。知识库 v1.0 原文不改，修订都是 `configs/knowledge/kb_versions/` 下的补丁版本。

## 4. 每轮流程

1. **分析**：教师只看 train。用 `bench.mirror_mine` 做两边对照的模式计数，读计数差异明显或与输局相关的例子。
2. **候选**：每条改动写明要改变哪种决策模式、在什么局面下改变。可改的层：
   - **策略层**：新增、修改、退役单元；
   - **接入层**：单元的优先顺序、注入位置等技术性改动；
   - **规则层**：只修技术问题，每条都经引擎核对。
3. **机制核对**（每个候选在 dev 之前做）：在该模式触发的 train 局面上（至少 60 个）比较候选与父版本，同时测 `none` 对 `none2` 的空白差。
   预期方向的差异必须大于空白差的两倍，且至少 5 个百分点；不满足的改动，在进入 dev 之前从候选里删掉。
4. **守门**（dev 之前，便宜）：
   - 情境题 `situ_v2d33` dev 总体不低于 −0.01，任一题型（≥ 40 题）不低于 −0.05；
   - 斩杀转化 dev（v2-dev 64 题 × 1 轮）不低于 −0.05。
5. **dev 门禁**（候选对 `none_new`，`mirror_dev`）：
   - 先跑第 0–39 对，胜率 < 0.55 则停止并拒绝；
   - 否则再跑第 40–79 对，80 对合计胜率作为候选的 dev 分数。
6. **选最佳**：dev 分数最高的候选为当前最佳。它必须同时高于 D34 测得的 v1.0 dev 分数（0.547，旧观测层）和上一轮最佳。

最多 3 轮。

## 5. 最终 test（只跑一次）

- **主测**：当前最佳对 `none_new`，`mirror_test150` 150 对。
  - 成功 = 胜率点估计 ≥ 0.70，且对层面的符号检验 p < 0.05（单侧，H1：胜率 > 0.5）。
  - 另报 95% CI。
- **观测层对照**：`none_new` 对 `none_old`，`mirror_test150` 第 0–79 对。
- **锚点**：当前最佳与 `v10` 各打 `anchor` 32 局。成对的符号检验若显示最佳**显著更差**（p < 0.05），则守门失败。
- **斩杀**：v2-dev 64 题，最佳对 `v10`，规则同上。

即使最佳版本的 dev 分数不到 0.7，test 也照样跑一次，并如实报告。

## 6. 预算与停止边界

- **总上限 200 元**（DeepSeek 余额实测）。为 test 预留约 105 元：主测约 75 元，观测层对照约 27 元，锚点与斩杀约 5 元。
- **进化部分上限约 95 元**（train 对局、机制核对、守门、dev 门禁）。
- **停止条件**：
  - 进化花费达到上限；
  - 连续两个候选的 dev 分数都没有超过当前最佳 0.03 以上；
  - 或已跑满 3 轮。
- 每次运行都设 `--max-cost`（按调用记录实时计）。只在非高峰时段调用模型（太平洋时间 02:00–17:00、20:00–22:00）。
- 预计超出 200 元时先问。

## 7. 已知风险（写在结果之前）

- D34 测得的 v1.0 对无知识只有 0.547（80 对，未显著），而目标 0.7 要求的效应大得多。**很可能达不到**，报告时如实写明。
- dev 被多轮重复使用，最佳版本的 dev 分数会偏高（赢家诅咒），所以以 test 为准。
- 观测层改动对双方相同，不会直接提高知识方胜率；对照组只用来估计观测层本身的作用。
