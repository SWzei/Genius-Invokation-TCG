# 小模型上的知识库提升

> 日期 2026-11-23 21:33 – 2026-11-24 05:05（太平洋时间）。环境：云端 2 核，`gitcg 0.21.0`。
> 设计、判据在任何对局之前登记于 `reports/review/2026-11_kb_d38_prereg.md`，之后只追加；登记后的每次调整都写在追加记录里。
> 本次只评估已有的知识库 v1.0（接入 `kbt3-trig`），**不做任何教师调整**，dev 结果不用于挑选或修改知识。
> 全部用免费档：没有调用 DeepSeek，也没有调用付费 GLM。模拟器内结果，不进强度验收（D1）。

## 0. 结论

1. **知识库对小模型没有带来显著提升。** 跑满 50 对的两个模型，主指标（胜利优先，平局按 K→H→D 判定）都不显著：
   - **GLM-4-Flash**：0.400 [0.263, 0.537]（20 胜 / 30 负），单侧 p = 0.94，**方向为负**；
   - **Gemini Decision 1**：0.460 [0.321, 0.600]（23 / 27），p = 0.76；
   - Holm 校正后两者都是 p = 1.0。只看胜负（W）分别为 0.500、0.530，平局对占 80%、74%。
2. **另两个登记模型没有结论**：Gemini 3.5 Flash Lite（每天 500 次请求）和 GPT-OSS-120B（Groq，每天 20 万 token）被免费档每日额度挡住，每天只够约 4 局和 1 局，按登记停止、不分析。
3. **Sonnet（隔离子代理，局面题）也不显著**：
   - 斩杀题 64 题：带知识库 0.922、不带 0.875，McNemar 单侧 p = 0.227；
   - 情境题 100 题：0.95 对 0.98，方向相反；
   - 不带知识库时已接近上限。这里用的是会话内 `sonnet` 档子代理，不是 Sonnet 4.6。
4. **唯一正向的线索来自派生事实，不是知识库**：GLM-4-Flash 的次要比较（知识库 + `facts=1` 对不带）主指标 0.580（p = 0.16），K 击倒差 p = 0.045。
   这是次要比较里的次要指标，有多重比较，**不算显著**，只作为下一步的假设。
5. **"小模型规则知识少，知识库增益更大"的猜测没有得到支持。**
6. **花费 0 元**：都在免费档内，按公开价目估算约 2.4 美元，只作参考；没有调用 DeepSeek（余额仍为 30.65 元）。

## 1. 问题与设置

- **问题**：D36 / D37 中知识库对 DeepSeek 的作用很小。小模型自身规则知识更少，知识库的增益会不会更大？
- **数据**：`mirror_dev200` 第 150–199 对（50 对，D37 之前从未用过）。所有模型用同一批对，按编号顺序跑。
  - 一对 = 同一种子、同样两副牌、同样座位，双方各坐一次座位 0。
  - 任一局出错、截断，或任一方应答率 < 90% 的对整对剔除，双方同等处理。
- **对比**：双方同一模型、同一观测层（`elements=1`），只差 `kb=kbt3-trig`。
- **主指标**：胜利优先，胜负平局时按 K（击倒差）→ H（生命差）→ D（伤害占比）依次判定（D37 §11 的规则）。
  - 脚本校准：A/A 40 对子样本拒绝率 0.027；n80 = 24 对（ε = 0.3）、303 对（ε = 0.1）。
- **判据**：每个模型主指标单侧符号检验 p < 0.05 记为"显著提升"；对完成 ≥ 40 对的模型做 Holm 校正，同时报告未校正值。
- **截止**：Decision 1 的截止时间（2026-11-24 10:00）和对的顺序事先固定，不按结果停止。

## 2. 模型与实际可跑的规模

| 模型 | 接入 | 免费档限制（实测 429 原文） | 结果 |
|---|---|---|---|
| GLM-4-Flash（`glm-4-flash-250414`） | 智谱 OpenAI 兼容接口，非思考，`reply=reason_first` | 10 并发无问题 | **50 对全部有效**，0 降级；主比较 + 次要比较（加 `facts=1`） |
| Gemini Decision 1 | Decisions API：不生成文本，对每个合法选项给概率，取最大者 | 每分钟 5 万输入 token | **50 对全部有效**（05:04 跑满，早于截止），0 出错、0 降级 |
| Gemini 3.5 Flash Lite | 思考强度 low，`reply=reason_first` | 每分钟 15 次、**每天 500 次**请求 | 跑了 4 局就用完当日额度，**停止，不分析** |
| GPT-OSS-120B（Groq） | 推理强度 low | 每分钟 8 千 token、**每天 20 万 token** | 约 1 局就用完当日额度，**停止，不分析** |
| Sonnet（隔离子代理） | 没有 Anthropic API 密钥，改用 Agent 工具的 `sonnet` 档子代理作答；**不是 Sonnet 4.6** | 每次决策都要启动子代理，整局不可行 | 改为带标准答案的局面题（§4） |

- Flash Lite 的前两次运行（`d38_lite`、`d38_lite2`）因客户端把每分钟限额误判为余额耗尽而降级，已作废并修正（§5），不分析。
- 若升级 Gemini / Groq 付费档，可以按同一设定重跑 Flash Lite 和 GPT-OSS-120B。

## 3. 对战结果

### 3.1 主比较：带知识库对不带（同模型）

| 模型 | 有效对（W 平局） | 只看胜负 W | **主指标 K→H→D [95% CI]** | 胜 / 负 | 单侧 p | Holm 校正 p | 因素挑选区间 | 理论区间 |
|---|---|---|---|---|---|---|---|---|
| GLM-4-Flash | 50（40） | 0.500（5 / 40 / 5） | **0.400 [0.263, 0.537]** | 20 / 30 | 0.94 | 1.0 | 0.340–0.520 | 0.100–0.900 |
| Gemini Decision 1 | 50（37） | 0.530（8 / 37 / 5） | **0.460 [0.321, 0.600]** | 23 / 27 | 0.76 | 1.0 | 0.420–0.620 | 0.160–0.900 |

- 生命差 H 的均值：GLM-4-Flash +0.004 [−0.081, +0.088]；Decision 1 +0.018 [−0.094, +0.130]。都很接近 0。
- 座位 0 胜率：GLM-4-Flash 主比较 0.48，Decision 1 0.52；每局平均回合数 8.4、7.0。
- 每次决策的输入 token（带 KB / 不带）：GLM-4-Flash 2,427 / 1,233，Decision 1 3,065 / 1,853。
- Decision 1 的伤害占比 D 单独为 0.600（p = 0.10），因素挑选上限 0.620（p = 0.06）。这些都是偏向 KB 的挑选或次要指标，不改变结论
- 详见 `reports/bench/d38_glm4_tiebreak.md`、`d38_glm4_metrics.md`、`d38_decision_tiebreak.md`、`d38_decision_metrics.md`。

### 3.2 次要比较：带知识库 + 派生事实对不带（只有 GLM-4-Flash）

| 有效对（W 平局） | W | 主指标 [95% CI] | 胜 / 负 | 单侧 p | 因素挑选区间 |
|---|---|---|---|---|---|
| 50（31） | 0.550（12 / 31 / 7） | 0.580 [0.442, 0.718] | 29 / 21 | 0.161 | 0.520–0.660 |

- 方向为正，但不显著。
- 单因素里，K 击倒差 0.610（p = 0.045），H 均值 +0.101 [+0.003, +0.199]，D 均值 +0.039 [+0.010, +0.069]。
  这是次要比较中的次要指标，且有多重比较，**不据此下结论**。
- 与主比较（0.400）对照，提示对 GLM-4-Flash 起作用的可能是派生事实（引擎技能预演），而不是知识库本身。
  这是事后观察，没有单独的 `facts=1` 对照，只能作为下一步的假设。

## 4. Sonnet 子代理：局面题

**方法**（写于任何作答之前，见预先登记 22:07 条）：
1. 新的 `answer-file` 接入把两种条件的全部提示原样导出；
2. 按条件、按批（每批约 20 题）交给互相独立的子代理，共 18 个（每种条件 9 批）。每个子代理只读自己的一批题、只写答案；
3. 用答案文件重跑同一评测，按原有规则判分。328 题都有可解析的答案，没有脚本代答。

| 题目 | 带知识库 | 不带 | 只有带 KB 对 / 只有不带对 | 单侧 McNemar p |
|---|---|---|---|---|
| 斩杀题（v2-dev 64 题，第一步是否在致胜路线上） | 59/64（0.922） | 56/64（0.875） | 5 / 2 | 0.227 |
| 情境题（`situ_v2d33` dev，种子 38 抽 100 题） | 0.95 | 0.98 | 0 / 3 | 1.0 |
| 合并 | | | 5 / 5 | 不显著 |

- 不带知识库时 Sonnet 已接近上限（情境题 0.98），知识库没有可见的增益。
- 斩杀题里"提前一到三步"的子集，带知识库 0.850、不带 0.700（各 20 题），方向为正，但样本太小。
- **局限**：每批题共享上下文，不是完全独立的调用；子代理只靠指令约束不读其他文件；这是题目评测，不与对战胜率直接比较。

## 7. 解读

1. **知识库提供的是规则文本，小模型用不上，或者本来就不缺。**
   - GLM-4-Flash 带知识库后，每次决策的输入约多 1 倍 token（2,427 对 1,233），结果方向为负。一个可能的解释是长文本稀释了对局面的注意力，这是推测，没有单独验证。
   - Sonnet 不带知识库时已经答对 98% 的情境题，知识库没有可以补的空缺。
2. **Decision 1 只能"读"知识，不能推理**：它对每个选项直接打分，知识库只能通过输入文本影响概率。结果与不带知识库几乎相同（W 0.530、H 均值 +0.018）。
3. **两个模型的平局对都很多（74–80%）**：同一座位两局都赢，说明座位与牌组的影响远大于知识库。胜利优先的判定已经把它们全部分出胜负，结论对因素选择不敏感：
   - 因素挑选区间：GLM-4-Flash 0.34–0.52，Decision 1 0.42–0.62；
   - 即使为 KB 挑选最有利的因素，两者的上限也都不显著（p = 0.44、0.06）。
4. **派生事实的线索**与 D37 不同：D37 中 DeepSeek 加 `facts=1` 没有提升（H 0.425）。GLM-4-Flash 更弱，引擎预演直接告诉它"哪个技能能击倒"，可能对它更有用。
   验证需要单独的 `facts=1` 对照（不带知识库），并在新的保留对上预先登记。
5. **建议**：
   - 知识库 v1.0 不作为小模型的推荐配置；
   - 如果要继续，优先验证"小模型 + 派生事实"（GLM-4-Flash 免费、可跑满），而不是继续扩知识库；
   - 若要测 Flash Lite / GPT-OSS-120B，需要付费档；
   - Sonnet 4.6 的整局对战需要 Anthropic API 密钥与预算。

## 8. 限制

- 只有两个模型跑满了对战样本；Flash Lite 与 GPT-OSS-120B 被免费档每日额度挡住，没有结论。
- 每个模型只有 50 对，能检测的大约是胜率 0.65 以上的效应。
- Sonnet 用的是会话内子代理（不是 Sonnet 4.6，也不是独立 API 调用），且只做了题目评测。
- Decision 1 不写理由，知识库只能通过输入文本起作用；它的行为与"读知识、再推理"的生成式模型不同。
- 第 150–199 对现在已经用过；今后的独立估计需要新的保留对。

## 9. 复现

```bash

    --subjects "llm:glm-4-flash-250414#kb=kbt3-trig,reply=reason_first,elements=1" \
               "llm:glm-4-flash-250414#kb=kbt3-trig,reply=reason_first,elements=1,facts=1" \
    --rival "llm:glm-4-flash-250414#reply=reason_first,elements=1" --rep-from 150 --replicates 200 --tag d38_glm4 --workers 10
# Decision 1（到截止时间为止，按完成的整对分析；bench.run 可续跑）
python -m bench.run --suite mirror_dev200 --subjects "llm:gemini-decision-1#kb=kbt3-trig,elements=1" \
    --rival "llm:gemini-decision-1#elements=1" --rep-from 150 --replicates 200 --tag d38_decision --workers 2
# 分析
python -m bench.metrics tiebreak --tag d38_glm4 --out d38_glm4_tiebreak
python -m bench.metrics report --tag d38_glm4 --out d38_glm4_metrics
# Sonnet 子代理：先导出提示（GITCG_PROMPT_DUMP），子代理分批作答后，用答案文件重跑同一评测（GITCG_ANSWER_FILE）

GITCG_PROMPT_DUMP=dump_kb.jsonl python -m bench.scenarios eval --name v2 --split dev --kinds lethal --subjects "$SK" --tag d38_sonnet_lethal_dump_kb
GITCG_PROMPT_DUMP=dump_none.jsonl python -m bench.scenarios eval --name v2 --split dev --kinds lethal --subjects "$S" --tag d38_sonnet_lethal_dump_none
GITCG_ANSWER_FILE=answers.json python -m bench.scenarios eval --name v2 --split dev --kinds lethal --subjects "$SK" "$S" --tag d38_sonnet_lethal
# 情境题同理：bench.kb_situ eval --model subagent-sonnet --kb kbt3-trig none --mode reason（选题：种子 38 从 dev 469 题抽 100 题）
```
